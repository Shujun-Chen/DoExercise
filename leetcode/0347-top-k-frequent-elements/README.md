# 347. Top K Frequent Elements

**难度：** Medium

## 题目描述

给定一个整数数组 `nums` 和一个整数 `k`，返回其中出现频率前 `k` 高的元素。可以按任意顺序返回。

题目保证答案唯一（出现频率前 k 高的元素集合唯一）。

**示例 1：**
```
输入：nums = [1,1,1,2,2,3], k = 2
输出：[1, 2]
```

**示例 2：**
```
输入：nums = [1], k = 1
输出：[1]
```

**约束：**
- 1 ≤ nums.length ≤ 10⁵
- -10⁴ ≤ nums[i] ≤ 10⁴
- k 的取值范围保证答案唯一存在

## 解题思路

### 直觉

要返回频率最高的 k 个元素，第一反应是先统计频率，再排序取前 k 个。但 `O(n log n)` 的排序未必是最优解——**频率的取值范围有限**（最多就是 n），可以用桶排序把它压到 `O(n)`。

### 桶排序思路（最优解）

**第一步：频率统计**
用 `Counter`（或 `HashMap`）把每个数字对应的出现次数算出来，得到 `count: num → freq`。

**第二步：按频率分桶**
建一个数组 `bucket`，长度为 `n + 1`。`bucket[i]` 里装的就是**所有频率恰好等于 i 的数字**。例如 `bucket[3] = [1, 5]` 表示数字 1 和 5 都刚好出现了 3 次。

为什么桶长度是 `n + 1`？频率最大就是 `n`（所有元素都一样），最小是 0（其实不可能，因为只统计出现过的数字），所以 [1, n] 都要预留位置。

**第三步：从高频桶往低频桶遍历**
从 `bucket[n]` 开始往前扫，把桶里的数字依次塞进结果集，凑满 `k` 个就结束。

### 为什么这是 O(n)？
- 统计频率：`O(n)`
- 把每个不同的数字放进对应桶：每个数字只操作一次 ⇒ `O(m)`，`m ≤ n`
- 遍历桶收集结果：最多遍历 `n` 个桶 ⇒ `O(n)`

没有任何嵌套循环级别的依赖，每一步都是一次线性遍历。

### 替代方案（用堆）

如果题目要求频率查询是「在线」的（边来边问），桶排序就不合适了，这种场景更常见的是 **小顶堆**：

1. 维护一个大小为 k 的小顶堆 `{(freq, num)}`
2. 每个数字尝试入堆：
   - 堆未满：直接进
   - 堆满了，且当前频率 > 堆顶频率：弹出堆顶，把当前数字入堆
3. 最后堆里就是 top k

时间复杂度是 `O(n log k)`，比桶排序差但比全排序好（`O(n log n)`）。

## 复杂度分析

- **时间复杂度：** `O(n)`，n 是数组长度。三步都是线性遍历，没有比线性更慢的操作。
- **空间复杂度：** `O(n)`。Counter / HashMap 装频率，桶数组长度 `n+1`，加起来 `O(n)`。

## Python 解法要点

- 用 `collections.Counter(nums)` 一行得到频率统计，比手写循环计数简洁。
- 桶用「列表的列表」：`frequency_buckets = [[] for _ in range(n + 1)]`。
- 桶用 `range(n, 0, -1)` 反向遍历，freq == 0 的桶不用看（里面不会放任何东西，因为我们只遍历出现过的数字）。
- 收集够 k 个立即 `return`，避免多算。
- 结果顺序无所谓，所以测试里用 `sorted()` 对齐标准答案比较。

## Java 解法要点

- 用 `Map<Integer, Integer>`（`HashMap`）+ `getOrDefault` 做频率统计。Python 的 `Counter` 在 Java 里没有直接对应物，得手动写。
- 桶数组用 `ArrayList<List<Integer>>`，每行再 `new ArrayList<>()` 初始化，否则 `bucket.get(i)` 会报 `IndexOutOfBoundsException`。
- 遍历条件写成 `result.size() < k` 而不是单独维护计数器，可读性更好。
- 返回类型是 `int[]`，所以最后要把 `List<Integer>` 转回去。
- `main` 方法里用 `assert` 做正确性检查，运行时记得加 `-ea` 启用断言。

## 经验总结

- 看到「前 k 个」关键词，先想**堆**；看到「频率有限」关键词，先想**桶排序**。
- 桶排序的桶下标设计很关键——这里用频率当桶下标，本质是「频率的取值小到能开数组」。
- 答案唯一这个条件在 LeetCode 里很常见，意味着不用处理「返回任意一个合法解」的歧义。
