# 1275. Find Winner on a Tic Tac Toe Game

**难度:** Easy

## 题目描述

A 和 B 在一个 3×3 的棋盘上玩井字棋(Tic-Tac-Toe):

- 玩家轮流在空格上落子,A 先手落 `'X'`,B 落 `'O'`。
- 当一行、一列或一条对角线上出现三个相同且非空的字符时,游戏结束。
- 当所有 9 个格子都被填满时,游戏同样结束。

给定一个长度为 `n` 的二维数组 `moves`,其中 `moves[i] = [row_i, col_i]` 表示第 `i` 步落在 `grid[row_i][col_i]`。要求返回:

- `"A"` —— A 赢
- `"B"` —— B 赢
- `"Draw"` —— 平局
- `"Pending"` —— 还有步可走,游戏未结束

可以保证 `moves` 始终合法且 A 先手。

## 解题思路

1. 用一个 `3×3` 的字符数组 `grid` 模拟棋盘,初始全为 `' '`。
2. 遍历 `moves`:
   - 偶数下标 → 当前落子玩家是 A(放 `'X'`);
   - 奇数下标 → 当前落子玩家是 B(放 `'O'`)。
3. 每落一子后立刻判断:是否存在某行/某列/某对角线全部被当前玩家字符占满。
   - 三行、三列、两条对角线,共 8 条线需要检查。
4. 一旦判定有玩家赢,直接返回 `"A"` 或 `"B"`,不再继续模拟。
5. 走完所有 `moves` 后:
   - 若共 9 步 → 平局 `"Draw"`;
   - 否则 → `"Pending"`。

**关键点**:`n ≤ 9`,所以即使每次都做 8 条线检查,总时间也只跟 `n` 线性相关,常数极小。

## 复杂度分析

- **时间复杂度:** O(n),n 为 `moves` 长度(1 ≤ n ≤ 9)。每步最多检查 8 条线。
- **空间复杂度:** O(1),只使用一个固定的 3×3 字符数组。

## Python 解法要点

- 用 `all(grid[r][c] == ch for c in range(3))` 检查一行,Python 的 `all` 配合生成器让代码很紧凑。
- 每步落子后立即调用 `check_winner`,不用等所有 `moves` 走完再判断,这样可以处理棋局提前结束的情况。
- `if __name__ == "__main__"` 块里附带 5 个测试用例,覆盖 A 赢、B 赢、平局、未结束、A 沿对角线赢这几种场景。

## Java 解法要点

- 用 `char[][] grid = new char[3][3];` 模拟棋盘,Java 里 `char` 数组默认初始值为 `'\u0000'`,所以要确保只在被赋值过的位置做比较(实际上我们只跟自己落下的字符 `ch` 比较,所以未赋值的格子一定不相等,不会误判)。
- 用一个 `boolean win` 标记当前轮是否已经检测到胜利,遇到一条就立即 `break`。
- 抽出一个 `check(Solution sol, int[][] moves, String expected, int idx)` 静态辅助方法做断言,失败时直接抛 `RuntimeException`,比单元测试框架更轻量。
- `main` 方法同样覆盖了 5 个场景:A 赢、B 赢、平局、Pending、A 沿主对角线赢。
