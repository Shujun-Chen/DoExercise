# 128. Longest Consecutive Sequence

**难度：** Medium

## 题目描述
给定一个未排序的整数数组 `nums`，返回数字连续的最长序列的长度（序列内元素的值是连续的，不要求它们在原数组里相邻）。
要求算法时间复杂度为 **O(n)**。

示例：
- `nums = [100,4,200,1,3,2]` → `4`（序列 `[1,2,3,4]`）
- `nums = [0,3,7,2,5,8,4,6,0,1]` → `9`（序列 `[0..8]`）
- `nums = [1,0,1,2]` → `3`（去重后是 `[0,1,2]`）

## 解题思路

### 为什么排序不行
排序是 `O(n log n)`，达不到 O(n)。但题目真正的难点不在「找连续序列」，而是「在不排序的前提下，O(n) 找到」。

### 关键观察：只从序列「起点」开始数
对于任意一个数 `x`，如果它属于某个连续序列，那么这个序列里一定有一个「起点」——也就是 `x-1` 不在数组中的那个 `x`。
换句话说：**不是起点的数，跳过即可**。这样一来，每个数最多只会被访问到一次（作为起点往后枚举）。

### 步骤
1. 把所有数放进 `set`，便于 O(1) 判断「存不存在」。
2. 遍历集合中的每个 `x`：
   - 若 `x - 1` 不在 set 中，说明 `x` 是某个序列的起点，从 `x` 开始不断 `y = y+1`，数到断掉为止；
   - 序列长度 `= y - x`，用它更新答案。
3. 返回答案。

### 为什么是 O(n)
- 建集合：O(n)
- 每个 `x` 只在「起点判断」时访问一次，在「作为别人后继」时最多访问一次 → 总共 O(2n) = O(n)

## 复杂度分析
- **时间复杂度：** O(n)
- **空间复杂度：** O(n)（哈希集合）

## Python 解法要点
- 用 `set(nums)` 而不是 `list`，集合的 `in` 是 O(1)，list 是 O(n)。
- `for x in s:` 直接遍历集合，避免数组里重复元素重复处理（虽然不优化复杂度，但少做几次 `if x-1 not in s`）。
- 注意 `nums = []` 的边界要返回 0，不能直接进循环返回 `longest = 0` 之外的别的值。

## Java 解法要点
- `Set<Integer>` 选用 `HashSet`，不能用 `TreeSet`（TreeSet 是红黑树，查询 O(log n)）。
- Java 集合要预 import：`import java.util.HashSet; import java.util.Set;`。
- `longest = Math.max(longest, y - x);` 是惯用写法；变量命名沿用题解里的 `y` 保持一致。
- 边界 `nums == null` 也兜了一下，提交时按需删除。

## 拓展：并查集写法
另一种思路是并查集：把相邻的数 union 起来，最后看最大集合的大小。但并查集要额外路径压缩、合并数组初始化，比哈希表方案代码量大且常数高，面试时优先写哈希表版本。
