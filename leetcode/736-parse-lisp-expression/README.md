# 736. Parse Lisp Expression

**难度：** Hard

## 题目描述

实现一个 Lisp 表达式解析器，计算表达式的整数值。表达式支持三种形式：

- **let**：`(let v1 e1 v2 e2 ... expr)` — 依次将变量 vi 赋值为 ei，返回 expr 的值。
- **add**：`(add e1 e2)` — 返回 e1 + e2。
- **mult**：`(mult e1 e2)` — 返回 e1 * e2。
- **整数**：可以是正整数或负整数。
- **变量**：以小写字母开头，后跟零个或多个小写字母或数字。变量名"add"、"let"、"mult"被保留，不会用作变量名。

**作用域规则**：变量作用域由括号嵌套决定。查找变量时，优先从最内层作用域开始，逐层向外查找。

## 解题思路

### 核心思想：递归下降解析

本题的难点在于递归地解析嵌套的表达式。由于表达式本身具有递归结构（子表达式可以是嵌套的表达式），使用递归下降解析器最为自然。

### 步骤分解

1. **识别表达式类型**：
   - 以数字或 `-` 开头 → 整数字面量，直接 `parseInt()`。
   - 以字母开头 → 变量引用，从内到外查找作用域。
   - 以 `(` 开头 → 复合表达式，读取关键字后分别处理。

2. **Token 拆分**：
   - 对于复合表达式 `(...)`，去掉外层括号后，需要将内容拆分成独立的 token。
   - 括号内的子表达式作为一个整体 token，通过平衡括号计数来识别。
   - 普通 token（变量名、关键字、数字）按空白分割。

3. **作用域管理**：
   - 使用栈结构管理多层作用域，每个作用域是一个 `{变量名: 值}` 的字典。
   - 进入 `let` 时压入新作用域，退出时弹出。
   - 变量查找从栈顶（最内层）向栈底（最外层）遍历。

4. **let 表达式的处理**：
   - 读取变量-值对：`v1 e1 v2 e2 ...`，依次绑定到当前作用域。
   - 最后一个 token 是返回值表达式。
   - **关键细节**：同一 let 中的后续变量可以引用前面绑定的变量（例如 `(let x 1 y x y)` 中 y 可以引用 x）。

## 复杂度分析

- **时间复杂度：** O(N)，其中 N 为表达式字符串长度。每个字符在解析过程中恰好被处理一次。
- **空间复杂度：** O(N)，递归调用栈深度与括号嵌套深度成正比，最坏情况下为 O(N)。此外作用域栈也占用 O(N) 空间。

## Python 解法要点

- 使用 `scopes` 列表模拟作用域栈，每个元素是一个字典。
- `parse()` 函数递归调用自身，处理嵌套结构。
- Token 拆分时通过平衡括号计数将子表达式作为一个整体 token。
- let 中变量绑定依次求值并加入当前作用域，后面的绑定可以引用前面的。

## Java 解法要点

- 使用全局索引 `idx` 指针进行单遍扫描，避免多次分配子串。
- `scopes` 使用 `List<Map<String, Integer>>` 实现作用域栈。
- `readToken()` 读取不含空白的连续字符序列。
- `parseInt()` 处理可能带负号的整数。
- let 的解析需要前瞻一个 token：如果下一个字符是 `)`，则当前 token 是最终表达式。
