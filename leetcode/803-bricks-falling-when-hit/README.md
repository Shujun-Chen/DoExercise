# 803. Bricks Falling When Hit

**难度：** Hard

## 题目描述

给定一个 m x n 的二进制网格 `grid`，其中 1 代表砖块，0 代表空格。砖块是"稳定的"，当且仅当：
- 它直接连接到网格顶部，或
- 它的四个相邻单元格中至少有一个是稳定的砖块。

给定一个击打序列 `hits`，每次击打会使对应位置的砖块消失。消失后，其他砖块可能不再稳定而掉落。返回每次击打后掉落的砖块数量。

## 解题思路

**核心思想：逆序并查集**

正序模拟每次击打后判断砖块是否掉落，复杂度很高。关键技巧是**逆序处理**：

1. **先移除所有被击打的砖块**，建立初始的并查集结构
2. **逆序恢复砖块**，每次恢复时记录新增连通到天花板的砖块数量
3. 新增连通数 - 1（自身）= 本次击打导致的掉落砖块数

**并查集设计：**
- 使用虚拟节点 `top = m * n` 代表天花板
- 第 0 行的砖块直接与 `top` 连通
- 合并时按大小优化（小树合并到大树）

**详细步骤：**
1. 复制 grid，将所有 hits 位置置为 0
2. 对剩余砖块建立并查集连通关系（上下左右）
3. 逆序遍历 hits：
   - 记录恢复前 `top` 连通分量大小 `before`
   - 恢复当前砖块，与四个方向邻居连通
   - 计算恢复后 `top` 连通分量大小 `after`
   - `result[i] = max(0, after - before - 1)`

## 复杂度分析

- **时间复杂度：** O(m × n × α(m × n))，其中 α 是反阿克曼函数，几乎为常数
- **空间复杂度：** O(m × n)，用于并查集和 grid 副本

## Python 解法要点

- 使用 `UnionFind` 类封装并查集操作，支持 `find`（路径压缩）、`union`（按大小合并）、`get_size`
- 复制 grid 避免修改原始输入
- `directions` 数组遍历四个方向，简化邻居访问逻辑
- 逆序恢复时注意：如果原 grid 在 hit 位置没有砖块（`grid[r][c] == 0`），直接跳过

## Java 解法要点

- 使用成员变量 `parent[]` 和 `size[]` 实现并查集，避免额外类开销
- `clone()` 复制 grid 行，避免修改原始数组
- `Arrays.toString()` 输出测试结果
- `Math.max(0, after - before - 1)` 防止负数结果
